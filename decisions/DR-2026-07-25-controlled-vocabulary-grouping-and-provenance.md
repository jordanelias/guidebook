## 1. Context — what the request exposed

The request was ordinary: group equivalent terms across languages, so that *corridor*,
*hallway*, *circulation route* and *Flurbreite* are recognisably one concept, and so that
*acoustic baffling* and *sound absorber* stop being two.

The register to do this already existed and was in use — `scripts/generate_search_queries.py`
builds per-language search queries from it, and the current research-matrix workplan names it
as the active blocker. But it had been built **parameter-first**: it held `corridor width` and
no `corridor`; it held reverberation time and sound masking and nothing for absorption. The
two examples in the request were both genuine holes.

Three findings emerged, in ascending order of seriousness. Only the first was asked for.

**Finding 1 — the vocabulary was the wrong shape.** Parameters without their elements cannot
group. 41 element-level concepts were missing.

**Finding 2 — the matcher was matching substrings.** When a slug had no item link, the
generator fell back to `lower(canonical_en) LIKE '%<slug word>%'`. That is not a synonym
lookup; it is a substring search, and it had been silently producing false matches:

| slug token | matched | via |
|---|---|---|
| `room` | head**room** clearance | substring |
| `ot` | vibr**ot**actile alert | substring |
| `aut` | dys**aut**onomia | substring |
| `read` | adaptable **Read**iness | substring |
| `and` | every canonical containing "and" | substring |

These were invisible because the generator prints *queries*, not the terms behind them. The
apparatus reported coverage it did not have: 38 of 106 slugs resolved to nothing at all, and
several of those that did resolve did so only through the noise above.

**Finding 3 — nothing recorded where an alias came from.** 881 aliases carried no provenance
marker; 789 of those were non-English. A reader could not tell whether a term had been lifted
from a national standards glossary, translated by a person, or generated by a model. This is
the more serious finding, because the failure mode is silent: **a wrong search term returns
zero results indistinguishably from an absent literature.** The apparatus cannot tell you it
searched with the wrong word.

The through-line matches the finding in `DR-2026-07-25-rendered-document-integrity-gate`: the
defects were mechanically checkable, and none of them was caught by reading the code.

## 2. Decision — the vocabulary carries elements, not only parameters

`terms` gains 41 element-level concepts (`TERM-048`..`TERM-088`), each with an English synonym
set and equivalents in the 14 established languages. Register totals: 47 → 88 concepts,
964 → 2367 aliases, 50 → 147 `term_item_links`.

Two structural rules follow from what went wrong while building it:

**2.1 A parameter and its element are distinct terms, related explicitly.** `TERM-002`
(corridor width) is a dimension; `TERM-048` (circulation route) is the thing dimensioned. Both
exist; each `scope_note` names the other. The same split now separates `TERM-012` (sensory
room, the designated facility) from `TERM-074` (withdrawal space, the wider provision), and
`TERM-016` (wheelchair user, the person) from `TERM-079` (mobility aid, the equipment).

**2.2 A relation between concepts is a pointer, never a shared string.** This rule was earned:
`TERM-074` was first authored claiming `quiet room` and its equivalents in thirteen languages —
strings `TERM-012` already owned. Two concepts sharing an alias is not a link; it is a
collision that makes retrieval ambiguous and the register self-contradictory. Narrowed, the
overlap surrendered, and the relation restated as a `NARROWER` pointer.

Population and project codes are the deliberate exception: `OFS` maps to both fatigue
(`TERM-053`) and dysautonomia (`TERM-054`) because searching that code *should* return both.
Those four rows are annotated as intentional so a later audit reads them as intent, not drift.

## 3. Decision — slug→term resolution is token-based, over aliases

The `LIKE '%…%'` fallback is replaced by token matching over each term's canonical name **and
its English aliases**, so the synonym chart itself drives retrieval rather than the canonical
name alone. Three components, each earned by a specific failure:

- **Token equality, not substring.** Kills every row in the §1 table.
- **A corpus-derived stoplist.** `environment` (31 of 106 slugs), `built` (30), `design` (19),
  `and` (9) carry no discriminating power here; without stopping them one term matched 30
  unrelated slugs.
- **A specificity rule.** When a slug matches on a token that is rare across the corpus,
  matches resting only on common tokens are discarded. Without it, `accessibility` alone
  dragged in seven unrelated terms.

Measured effect: slug coverage **68/106 → 106/106**; terms per slug from up to **12** shotgun
matches down to a mean of **1.8**.

The stemmer is deliberately crude and deliberately guarded: it must not strip the final `s`
of *access*, *cross* or *analysis*. An earlier version did, and produced `acces` and `cros`
as match tokens — a new false-positive class introduced by the fix for the old one. Recorded
because it is the characteristic risk of this kind of repair.

**Six aliases were reworded because the alias was itself the false-positive source** — most
plainly `resting place`, which collided with "Changing **Places**". When a synonym causes a
bad match, the synonym is the defect; widening the stoplist to hide it would suppress the
signal everywhere else.

## 4. Decision — an alias must declare where it came from

Every alias created on or after **2026-07-24** carries a provenance marker in
`term_aliases.notes`. Earlier cohorts are grandfathered and reported, not failed — the same
backfill-on-touch convention the attestation system uses, so this lands as a forward
commitment rather than a demand to retro-document 880 rows before anything else can move.

Recognised markers, adopting `references/native-alias-verification.md` rather than inventing a
parallel vocabulary, so `MODEL-GENERATED` has a defined exit instead of being permanent:

    MODEL-GENERATED  ->  VERIFIED-GLOSSARY  (national standards body glossary)
                     ->  VERIFIED-NATIVE    (qualified native-speaker review)
                     ->  VERIFIED-CROSS     (corroborated across published sources)

**Every non-English alias this session produced is model-generated and flagged as such.** They
are a retrieval aid, not authoritative terminology, and the generated chart carries that
statement so the caveat travels with the artefact rather than living in a conversation.

`scripts/audit/alias_provenance_audit.py` measures this per language and fails on an unmarked
post-cutoff alias. On its first run it failed a row written earlier in this same session — a
`NARROWER` pointer with a relational note and no provenance. That is the intended behaviour
and is the reason to prefer a gate over a resolution.

## 5. Decision — three gates, and a corrected claim

**5.1 The vocabulary layer is visible to the structural audit.** `terms` was registered as a
node kind, so 47 term nodes existed — with **zero edges**. Every one was an isolated island.
`term_item_links.item_code` carries no FK constraint, so a row pointing at a nonexistent item
was invisible to the FK passes *and* to the graph audit simultaneously. `extract_db.py` now
emits vocabulary edges; 88/88 term nodes are connected.

**5.2 `GUIDEBOOK_DB_PATH` is enforced, and `CLAUDE.md` §7 corrected.** §7 claimed "Every
DB-aware script honours `GUIDEBOOK_DB_PATH`". It was false for 9 of the live DB-connecting
scripts, and the cost was not hypothetical: a reach test in this session pointed at a scratch
copy, silently read the committed database, and reported "no change" for a change that had in
fact taken effect. Nine scripts fixed and verified to redirect;
`scripts/audit/db_path_env_audit.py` added (level 2, blocking in CI).

Two exemptions, documented in the script rather than silent: `assess_cell.py` requires `--db`
and actively refuses the canonical DB, so honouring the variable would defeat that guard;
`graph_audit.py` resolves the path through `graph/build.py`. The second declares
`delegates_to`, so it **self-invalidates** — if the delegate regresses, the exemption reports
STALE and the audit fails rather than covering for it. Verified by regressing the delegate
deliberately.

§7 now also records that `scripts/db/**` targets `data/db/guidebook.db` — a *different, legacy*
file that is not the canonical database and must not be redirected by this variable.

**5.3 Both gates and the provenance audit are blocking in `audit.yml`.** Steps in that workflow
set `GUIDEBOOK_DB_PATH` explicitly, so a script ignoring it reads whatever is on disk rather
than what CI intended — the contract is load-bearing there, not decorative.

## 6. Raised, not decided

**6.1 A structured `verification_status` column (D-SCHEMA — Change-Order gated).** Parsing
provenance out of a freeform `notes` string is weak: it cannot be constrained by a CHECK, and
it cannot be joined against. A first-class column with an enum would be better. Adding one is
a schema Decision and Change-Order gated (`CLAUDE.md` §4), so it is **proposed here and
recorded in GAP-303's `shift_conditions`, not executed.**

**6.2 Vocabulary for AR / BN / HI / ID / SW (owner input owed).** `lang_jur_map` requires five
languages that hold **zero** aliases. Their search coverage is therefore *structurally* zero,
not `NOT-RUN` — the generator cannot emit a query without vocabulary. Registered as **GAP-302**,
naming the candidate glossary per language (AR: SBC / ECP 306; HI: MoHUA Harmonised Guidelines;
ID: SNI 03-1746 / PUPR 14/2017; SW: TZ/KE national codes; BN: BNBC 2020).

**These were deliberately not model-generated.** Producing controlled vocabulary in languages
nobody on the project reads would be unfalsifiable by construction: no one here could detect a
wrong term, and the failure mode is a silent zero-result search that looks exactly like an
absent literature. That is fabrication with extra steps, and it is barred by the citation
discipline ("I don't know" > invention). Sourcing them from published glossaries is real work,
now registered rather than carried as a caveat.

**6.3 No alias has reached a VERIFIED-* state, in any language.** Registered as **GAP-303**,
P2. Multilingual retrieval currently rests entirely on unconfirmed terminology. The P1 order in
`references/native-alias-verification.md` (DE/FR/JA/ZH/KO — languages with national standards
bodies publishing terminology) is the recommended starting point. **Owner direction owed on
sequencing and on who performs native review.**

## 7. Adversarial pass (one pass, this version — R2 / DR-2026-05-09)

- **Objection: 41 new concepts is register inflation — the repo's named failure mode.**
  **Answer:** partially conceded, and it is why the count is *measured* rather than asserted.
  Each concept is justified by a slug that previously resolved to nothing or to noise; coverage
  went 68→106 with mean matches *falling* from a 12-match maximum to 1.8, which is the signature
  of added precision rather than added bulk. The genuine inflation that did occur —
  `TERM-074` duplicating `TERM-012` — was caught and corrected in §2.2, by an audit, not by
  reading.
- **Objection: the collision audit was run before the build and not after, so the duplication
  shipped and had to be fixed forward.** **Answer:** conceded without qualification. This is the
  clearest process failure of the session: a check that exists is worthless if run only at the
  point where it cannot fail. It was found only because the owner asked whether everything had
  been resolved. The corrective is structural, not a resolution to be more careful — the audit
  is now in CI, where it runs after every change by construction.
- **Objection: the stoplist is tuned to the current 106 slugs and will drift as slugs are
  added.** **Answer:** true, and it is the weakest part of §3. The document frequencies are
  computed live from `slugs` at query time, so the *specificity rule* adapts automatically; the
  hardcoded stoplist does not. Recorded as a known limit rather than hidden. It fails safe:
  a stale stoplist costs precision, not coverage.
- **Objection: §4 grandfathers 880 rows, so the register is mostly unattested and the gate is
  mostly decorative.** **Answer:** conceded as to the present state, denied as to the trend.
  The alternative — blocking until 880 legacy rows are retro-documented — is how a convention
  gets abandoned. Backfill-on-touch is the convention the attestation system already uses for
  the same reason, and the audit prints the outstanding count every run rather than letting it
  fade.
- **Objection: flagging 1163 aliases "model-generated, pending review" makes unverified
  terminology usable while looking rigorous.** **Answer:** this is the strongest objection and
  it is not fully answerable. The mitigation is that the flag is machine-readable and counted,
  the chart states it in the artefact, and GAP-303 tracks it as owed work at P2 — versus the
  prior state, where 789 non-English aliases carried no marker at all and nobody could have
  asked the question. Labelled-unverified is strictly better than unlabelled; it is not the
  same as verified, and §6.3 says so.
- **Refutation test.** Falsifiable and verified before commit: (a) revert the token matcher and
  `room`→headroom returns; (b) regress `graph/build.py` and the `graph_audit.py` exemption
  reports STALE and the audit exits 1; (c) insert an alias with empty notes and
  `alias_provenance_audit.py` exits 1; (d) `migrate_db.py --rebuild` reproduces every count.

## 8. What this DR does NOT do

- Does **not** change any evidence state, cell, grade, tier, or population code. No BPC, no
  `evidence_cell_state`, no `convergence_assessment` row is touched.
- Does **not** coin any population umbrella. New terms are built-environment elements,
  parameters, methods and symptoms; named conditions (`stroke`, `multiple sclerosis`) are
  retrieval aliases explicitly marked as such, never population labels
  (`CLAUDE.md` §10; `DR-2026-07-22-work-from-axes`).
- Does **not** add vocabulary for AR/BN/HI/ID/SW — see §6.2.
- Does **not** verify any translation. Every non-English alias added remains model-generated.
- Does **not** alter `lang_jur_map` or which languages are required — that is DG-NON.
- Does **not** sweep `GUIDEBOOK_DB_PATH` through `scripts/{db,migrate,probes,test}/**`. Those
  are one-time/legacy and out of the audit's scope by the same `EXCLUDE_PARTS` the code-layer
  audit uses; `scripts/db/**` additionally targets a different database file.
- Does **not** resolve the 9 pre-existing `test_db_integrity.py` failures — verified identical
  on the pre-change baseline, all in `evidence_sources`/`gaps`, unrelated to this work.
