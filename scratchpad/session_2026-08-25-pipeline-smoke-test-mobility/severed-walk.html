The pipeline is not slow, or partial, or behind schedule. It is severed: two stages of real work, two consecutive stages at absolute zero, and a render layer whose 126 rows were never produced by the pipeline at all.

But a row count only says a stage is empty. The question that decides what to do is different, and it has to be asked per stage: would this stage work if you handed it perfect data?

Read the second row against the third and fourth. Evidence collection fails on a day’s work. Judgment and synthesis fail on a missing writer and a broken engine. That is the difference between “the batch runs once we add flags” and “the batch stops at the hinge whatever we do” — and conflating them is how a batch gets started that cannot finish.

Where it actually stops

One column earlier than it looks

The obvious reading is that the break sits between evidence collection and judgment, because specifications is empty and has no writer. That reading is wrong, and acting on it would fix the wrong thing.

source_value_extractions is specified in fourteen places and written by nothing

It has its own Pydantic model. It feeds the value-directness dimension of the conditioning calculation. It is named in the pipeline contract, the pipeline map, the context map, evidence-architecture.md, evidence-methodology.md and project-standards.md. Two views read it. And no script, no CLI subcommand, and no committed migration has ever put a row in it — the three migrations that name it carry DDL only.

grep -rlE "INSERT INTO source_value_extractions|UPDATE source_value_extractions" --include='*.py' --include='*.sql' . → no output

This table is the join between “we found a paper” and “the paper says 1200 mm.” It sits at the end of the evidence-collection row, not the start of judgment. Until something writes it:

  • convergence can only count documents, never independent values — which evidence-methodology.md §3 expressly forbids;
  • v_value_independence returns 0, so the research frame’s own success criterion (“≥1 bucket with ≥2 independent roots”) is unreachable by construction rather than by shortfall;
  • a specifications row, if one could be written, would carry a value that no source is recorded as having stated.

The project diagnosed this itself on 12 July and wrote the diagnosis into its own data — three convergence_assessment rows carry the rationale “Value-level convergence not yet assessable… assessment queued, not assumed.” That is exemplary practice: the absence recorded as data rather than papered over. It has been queued ever since.

Corridor widths, door thresholds, sloped surfaces, flooring, handrails — every one is a quantity. The single stage that turns a source into a quantity with a locator attached has never run.

The finding that outranks the machinery

MOB is the umbrella the rule was written to abolish

populations holds 23 codes. Three are mobility: LMB (limb differences), SCI (spinal cord injury), and:

MOB — “disabled people with mobility needs; wheelchair users”
“General mobility limitation including walking, balance, or wheeled mobility”

There is no code for ambulant disabled people, and none for part-time wheelchair users. Now read the provenance clause of the rule that forbids exactly this, in project-standards.md:

Broad umbrellas… are forbidden as profile codes: they collapse opposed and orthogonal design demands and erase specific communities… Provenance: three self-caught erasures — “physically disabled/wheelchair users” erased the ambulatory and part-time-wheelchair disabled and buried the orthogonal upper-limb/reach axis. In each case the axis layer already held the distinctions the umbrella destroyed.

The axis layer still holds them — AX-AMB, AX-WHM, AX-BAL, AX-REA. But cells are keyed (item × population), so all four distinctions collapse at the moment a judgment is written, because the judgment’s key is MOB.

ItemDemands MOB collapses
Corridor clear widtha wheelchair user’s turning and passing envelope; an ambulant crutch or walker user’s swing width; a balance-disorder user’s need for a wall within reach
Handrailsserve ambulant and balance users first — the exact groups MOB erases — and are an obstruction to some wheeled users
Sloped surfacesopposed: a manual wheelchair user wants a shallower gradient; an ambulant person with fatigue or spasticity often wants a shorter run, and therefore a steeper one
Flooringfirmness for wheeled rolling resistance; slip resistance for ambulant gait; low LRV differential for dementia wayfinding
Door thresholdsnear-universal, but tolerance differs by castor size versus toe clearance

A batch keyed on MOB averages opposed demands and reports the average as best practice. That is the failure the two-layer taxonomy exists to prevent, and it is one INSERT away.

This is the one finding here where the right answer is not obvious to me. Minting codes for communities is co-production work, not a schema edit, and “nothing about us without us” governs who may name them.

<h1>Corridor Clear Width (≥1200 mm Minimum on All Primary Routes)</h1>

1200 mm — below the regulatory floor the doctrine names, and half the best-practice anchor it names, on the flagship item of the batch about to run. The page’s body correctly says the value is not yet computed; the heading above it asserts a figure. One trace graded the banner and never read the heading; another found the heading; a third found the doctrine it contradicts. No single pass would have caught it.

The repair plan

Making it walk in both directions

Code and wiring only — every item below meets the repository’s own test that code needs evidence, not permission. Organised by edge rather than by stage, because this pipeline re-enters stages: a stage that works in isolation can still leave the walk unable to come back round.

The backward edges are the worse half, and none of them show up in a row count. Each is a path by which a later finding should change an earlier record, and does not.

Phase 2 — backward

The re-entrant edges

What the census cannot show. This is the half that lets the pipeline revise itself.

  1. Mining drops its yield. 138 DOIs harvested, 4 in the clue store, 134 stranded — plus 256 mobility leads in an .ignore-hidden directory. connections_produced is written only by migrations and read by nothing. Needs a promotion edge; never promote the truncated title_short.
  2. Nothing compares a determination to the synthesis citing it. Ten scripts touch both tables; all are renderers or counters. No comparator exists.
  3. Stale-synthesis propagation is built and has never run. supersession_check has a writer, a subcommand and zero rows. This one needs running, not building — the cheapest item here.

  5. opus_reviewed is dead — hardcoded 0, never read, while Part 5 renders a pending connection’s text verbatim. Make it real or delete it; do not leave a field that looks like a safeguard.

The plan’s own acceptance test fails by construction

I wrote that after Phase 0 and Phase 1 this would be walkable on a scratch copy: one source admitted → one value extracted with a locator → one cell with governing_refs → one synthesis → one rendered page showing the value and its sources. An adversarial review traced it against the code. It does not complete, and it fails at the last step:

$ grep -c "value" scripts/generate/spec_page.py
0

The renderer never selects or shows the value. Its table carries state, tier and sources — no value column. A perfect determination renders a page with no number on it. And the only existing writer, assess_cell.py, binds literal None for value_min, value_max and value_unit — so there is nothing to show even if the page could show it.

Nothing in Phases 0–4 would have caught this, because nothing in the plan read the renderer. Five additions close it, all Phase 1: render the value, bind it, add the convergence and confidence refusals the blocking gate actually demands, write the root fields v_value_independence counts, and reconcile the verification-method choices with invariant I4.

The one that matters most is the third. A green path that stays unreachable while the gate stays red is precisely the condition that produced the fabrication of 19 August: the writer could not express what the gate demanded, so someone wrote it by hand.

One item was withdrawn outright. I had claimed stale-synthesis propagation was “built and never run” because supersession_check exists. Read from its CHECK constraints, that table records literature currency for an anchor source — is this still the best available paper? It cannot express “a judgment changed, so the synthesis citing it is stale.” The original verdict of ABSENT was right and I overturned it by reading a table name instead of its schema — the exact error the repository’s own rule about vocabularies warns against.

Phases 3 and 4 — render truthfulness and apparatus honesty — are real and none of it blocks a batch. Two of them are minutes: room_page.py queries FROM room where the table is rooms, and index.html hard-codes counts that are wrong today.

The plan adds no check, no table, no register and no workplan file. Every item repairs something that exists or writes a table that exists. Where the honest answer is deletion, that is offered as the equal option — which is the whole reason this repository is allowed to shrink.

Fairness

What works, stated as plainly as what does not

The anti-fabrication machinery does what it was built to do

A real mobility source was admitted end to end — Sanford, Story & Jones 1997, Ramp Slope on People with Mobility Impairments — retrieved through the logging fetcher with a byte-identical hash to an independent curl, and author verification returned CLEAN. This is the one part of the pipeline designed in response to a real failure and then tested against one.

Also genuinely working: the five-link write path, exercised end to end on a scratch copy with a real mobility-shaped batch — the delta capturer sees UPDATEs and refuses whole-batch on any DELETE, and deep reproducibility passes 66/66. The search logger refuses a count that disagrees with its admitted-id list. preflight.sh runs the selftest that --changed-from skips. Citation mining genuinely runs backward and forward. And the attestation gate caught this very session’s own omission — correctly, and blocking.

The gates are thickest around the database and thinnest exactly where the reader is: index.html, parts/v10 and site/rooms are unguarded, and two of the three are measurably wrong today.

Method

How this was run, and what it got wrong

Six stage agents traced one pipeline stage each — every script, skill, hook and gate they could reach — writing to per-agent scratch copies. Three read-only auditors then contextualised the traces against the repository’s own doctrine. Nothing was admitted; the committed database’s hash is unchanged.

The traces were not taken on trust. Load-bearing claims were re-derived before being repeated, and that changed several of them:

RULE
Whether this session should exist at allOwed and unwritten

A standing rule restricts any commissioned pass to a diff that wrote research rows or amended a synthesis artifact, and states plainly that a pass on a pass is forbidden. This is an apparatus audit with three auditors reading six traces — outside the rule on both counts. It is lawful, because a live owner instruction supersedes a prior ratified record on contact. But that same rule says the job on hearing one is to record the supersession, and I did not — for the whole session, until an auditor cited the rule I had never read. The record is now written, scoped to this session alone.

That is three times in one session that the record held something my search did not reach. The pattern is not carelessness about any one file: I searched code exhaustively and prose opportunistically, in a repository whose binding decisions live in prose.

The strongest objection to this exercise is that it is the pathology it describes: seven agents, six thousand lines of audit, zero determinations, in a repository whose own diagnosis is that it pays for meta-work and charges for research. That objection holds as a price and fails as a prohibition. It holds because the tax is real and three of these findings merely rediscovered recorded ones. It fails because roughly half are new, verified, and directly de-risk the batch — and because a defect found before a batch costs an afternoon, while the same defect found during one costs the batch.

The findings are worth exactly the batch they unblock. If they become the next register instead, they were not worth writing.
