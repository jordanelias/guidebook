# PR body notes, step 4.1, and the plan items not built (with reasons)

## 4.1 (`stack/4.1-verbs-diet`)
Deleted: `db.py migrate` (shells out to `scripts/migrate_db.py`, the real runner), the usage lines for `init` and `validate` (retired 2026-08-15; a script compares the docstring's verbs against the parser's: `init`, `validate` and `--help` were the only three that did not resolve, and `--help` is not a verb), and `update_gap_priority` (an AST search of every tracked Python file finds no reference to it by name or as a string; it restated the priority vocabulary in a tuple). CLAUDE.md rule 8 no longer lists `amend-source --tier` among values the machine could derive.
**Why so little.** Over the tracked command logs, 14 of 72 verbs ran three times or fewer (re-derive: parse `sub.add_parser("...")` from `scripts/db.py`, count `db.py <verb>` in `scratchpad/*/commands.jsonl`). The other thirteen are each the only verb that performs an act on a live table (`add-alias`, `amend-term`, `rename-term`, `raise-follow-up`, `resolve-follow-up`, `revoke-declination`, `resolve-determination-gate`, `delete-connection`, `update-connection`, `update-conflict`), or a reader that a live skill tells agents to run (`gaps`: five skills; `conflicts`: cross-population-conflict-mapper; `unmined-gaps`: gap-driven-mining). Deleting any of them would leave a table unwritable or a skill pointing at nothing (rule 4).
**Erratum to the commit message and the paragraph above.** Four of the thirteen kept verbs (`delete-connection`, `add-alias`, `amend-term`, `rename-term`) are named by no skill, machine or capability, and their tables have other writers. They were kept because each is the CLI's only route for a correction (CLAUDE.md section 4: a correction without a verb is hand SQL against a table the CLI can reach), and `add-alias` and `rename-term` have cases in `test_scan_contract`. The commit message's "every one is the only writer of a live table" is wrong for them. `architecture/sqlite-data-layer.md` (a 2026-05-05 design record) still documents `db.py migrate`, `init`, `validate` and `update_gap_priority`; it declares itself a design for implementation and was not edited.

**Gate G3.** `wc -l scripts/db.py` reads 9,898 after this step (the commit message says "about 9,700"; commits cannot be amended here). The verbs are not the cost: the cost is narrative comment inside functions. Gate G3 asks whether to reconsider the rewrite for `db.py` alone; that is the owner's, and 4.3 is the cheaper alternative.

## Not built, and why
- **3.R, the renderer.** (1) There is no live determination to render: all eight `specifications` rows are retired, and the plan itself says a view over them returns zero rows. (2) The ratified register map (`REGISTER_MAP` in the deleted `scripts/generate/pilot_renderings.py`, text of DR-2026-07-21 and G8) is keyed on tuple classes that predate the marker: it prints T3-clinical-alone as "Provisional [◐]", while tier-system section 5 and step 3 specification band it ● (provisional ●), and it has no class for a proxy inference. Porting it would either carry a band error into a new file or rewrite claim-strength language for six audiences, which is doctrine text (CLAUDE.md section 8: audience, CRPD posture). (3) Probe P-K stays NOT-BUILT. The migration that adds `marker` already makes `v_best_practice` carry it, so the data the renderer would read is in place. **Owner decision needed:** the register text for ◐/●/○ per audience.
- **4.3, comment diet.** The plan says skip unless review time is available, and a comment's "why" cannot be told from its history by a heuristic; a mechanical pass would delete rationale.
- **4.4, the walkability check.** The plan registers it only when the set it prints is empty or every member is a named residual; `walkability.py` still lists orphans (`access_duration`, `access_stakes`, `conflicts`, `data_migrations`, `decisions`, `life_stage_modifiers`, `research_code_leads`, `rooms`, `source_locators`, `weighting_profile`). A check that is red from the day it lands is the pattern rule 6 warns against. `graph_audit` stays.
- **4.5, centralised bindings.** `dbcore` already exports `REPO_ROOT` and `db_path()`. The 67 files that read `GUIDEBOOK_DB_PATH` and 47 that define a root use at least six spellings, and `scripts/audit/db_path_env_audit.py` enforces the per-file contract by AST, so the audit has to learn the new form before any file changes; the saving is two or three lines a file.
- **Phase 5 (research).** Re-retrieval of the legacy sources, the WHO payloads for the medical registry, the missing admissions and the 468 unread (source, parameter) pairs are research acts that need network retrieval and judgment about sources, and each needs a session record and an attestation (CLAUDE.md rule 2). The one offline item, the `annotate-parameter` correction for parameter 12, is a data migration that must ship in the research pull request, not with these tooling pull requests (rule 10).
- **Phase 6** waits for `conflicts.yaml` to be empty; `grep -c '^- id: C-' workplan/pipeline-state-graph/conflicts.yaml` gives what remains.
