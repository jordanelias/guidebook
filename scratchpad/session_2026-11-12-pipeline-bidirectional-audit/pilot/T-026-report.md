2. **AT-24 names no query, and its natural test passes vacuously.** "No alias marked as a model seed is returned by the vocabulary query the writers use" does not say which query. I chose `_near_terms` (the only vocabulary query section 4 item 2 names; `_name_holder` is T-028's, see `T-028-design.md` section 8 and case T028-05). A seed has to be made by SQL on the scratch copy for the case to be able to fail. Fixed in the test; the file should say so and name the probe recipe (words that appear in no name, two tokens, then a superset query).
3. **Item 2 ("`_near_terms` and `alias_provenance_audit` read the column, not the note") cannot be followed as written, and is half untrue.** `_near_terms` reads no note (`sed -n 6419,6440p scripts/db.py`); it reads `canonical_en` and every EN alias. The audit cannot read the column alone: the design's fill maps `curated`, `repo shorthand` and `VERIFIED-*` rows to `unrecorded`, so a column-only audit would classify them UNKNOWN. By my count of `classify()` over the clone before the migration: 1163 MODEL-GENERATED, 880 UNKNOWN (all before the cutoff), 304 CURATED-EN, 20 PROJECT-CODE, 15 VERIFIED-GLOSSARY, the last three groups all created on or after `CUTOFF_SESSION_DATE`. That is a decision the file and the design should have made: the mapping loses three classes.
4. **"Do not weaken a refusal" (section 8) contradicts AT-24.** Filtering seeds out of `_near_terms` makes the near-match refusal at `add-term` stop firing on every model-generated and curated EN alias (the screen now compares labels and attested forms only, and no form is attested today). 5. **The junction cannot reference `term_aliases` "by rowid".** Section 4 item 1 says it "references `term_aliases` by `rowid` until T-028". SQLite refuses a foreign key on a rowid: I ran `create table q(.., foreign key(y) references p(rowid))` and an insert gave `foreign key mismatch - "q" referencing "p"`. So there is no FK; the writer (`log-search --form-id`) is the only check. Also `term_aliases` has no INTEGER PRIMARY KEY, so its rowids are not guaranteed stable across a `VACUUM` or any table rebuild; the junction's meaning rests on T-028 copying `rowid` as `form_id` before anyone runs either. The file should say this and name the table and column (`search_execution_forms`, `form_id` were my choices, following the `search_admissions` shape).
