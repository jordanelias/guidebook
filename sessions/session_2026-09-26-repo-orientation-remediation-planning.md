4. **Root-cause survey.** A second fable 5.1 read-only session surveyed the repository, its PRs, and the governance apparatus against the recurring pattern of defects being caught by adversarial review rather than by any gate, and by history rather than by any check. It returned six root causes (RC1–RC6, see the DR for the full finding text), with RC4 — the adversarial pass itself has no record and no enforcement — named as the most load-bearing, because RC1's specimen (GAP-050/051) was only caught by a pass that was optional and, on inspection, not actually independent (batch 20's "different model" antagonist ran on the same model as its author, `claude-opus-5-5`, contradicting `.claude/agents/antagonist.md`'s declared `model: fable`).

Reviewed on explicit instruction ("review for errors then execute carefully in full") by an independent adversarial pass, which returned eleven findings (F1–F11). The most severe, F1, was that the RC1/RC5 acceptance test as designed could never go red on the historical specimen it claimed to demonstrate on, because the field it depended on was never backfilled and backfilling it would mean editing committed artefacts — the exact practice the DR itself exists to stop.
6. **DR v2**, rewritten to fix F1–F11. Verifying those fixes against the live repository surfaced twelve further problems (N1–N12) the review had not raised, the most consequential being N1: a search does not exist in the database when the payloads it returned are fetched and logged, which invalidated v1's entire manifest-field design for linking a candidate to the search that surfaced it. v2 moves that edge into a new junction table (`search_execution_artefacts`) recorded when the search itself is logged, instead.
