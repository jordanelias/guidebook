## 3. Rules every step obeys

- **W1 Evidence and callers in the same change.** A deletion's commit carries the command and its output (CLAUDE.md §8). The sweep (§9, "Caller sweep") covers the name and its import forms (including lazy imports and imports inside `schemas/` itself: the AST closure in `rehearsals/F-r5-r22-r30.md`), `.github/`, `.claude/`, `governance/*.yaml` (the registry, the contract, `schema-reference-exemptions.yaml`, `known_debt.yaml`), `schemas/`, the skills, views and triggers in `sqlite_master` (read their SQL; `schema_reference_audit` reads scripts, not view bodies, and it misses SQL split over implicitly concatenated string literals and reads guarded by `_table_exists`), the blocking readers (`scripts/tests/test_db_integrity.py`, `schema_reference_audit`) and the prose that names the object. Those edits land in the same PR, and a new table is mapped in `governance/stage-map.yaml` in the PR that adds it. **The sweep is run after the deletion, not before.** §5a records what the rehearsals found; re-derive it at execution, because it goes stale.
- **W2 Order by the graph.** Children before parents along each foreign key; for repairs, stages in spine order unless §5 names the dependency that overrides it (T1 and the root pointer, which is judgment's, land first; the identity rename, which is base's, lands last). Where a table's stage-map placement and its foreign keys disagree (`items`), the foreign keys decide.
- **W3 Net-negative.** A PR touching `scripts/`, `tools/`, `schemas/`, `.github/` or `skills/` must not raise the row totals above unless its step names the exception and the code it replaces (the exception may replace none, and then says so). Enforced by review, not by new code (CLAUDE.md §8).
- **W4 Done = probes, and the instrument is a gate.** Each step names the probes or predicates it must turn `PASS`, or delete with their subject. After each PR: `python3 workplan/pipeline-state-graph/build_graph.py --check` and `--selftest` (the latter is in no gate, and two of its fifteen tests broke when Phase 1 dropped the tables their fixtures named), `run_checks.py --changed-from origin/main --explain`, and `run_checks.py --selftest` after any rename or registry edit. **`build_graph.py --check` fails on three things the v3.3 lists did not name:** a quote an atom cites from a file the step edits (CLAUDE.md, the contract, the architecture document); a `file:line` an atom cites that moves more than 3 lines (removing 5 lines from `pipeline-contract.yaml` fails 13 atoms); and a stage-map entry for a dropped table. A step that edits such a file commits `ATOMS.tsv` and the edited atom files, reverts the timestamp noise `build_graph.py` writes into `STATE-GRAPH.md` and `graph.json`, and **regenerates the instrument last**, because every PR that regenerates it conflicts with every other that does.
- **W5 Rule 10 and rule 9.** Tooling PRs first and merged; the research PR last. One PR at a time, opened last, `unsubscribe_pr_activity` straight after. No history rewriting (`git merge origin/main`, not rebase). A PR that changes the database commits the rebuilt blob only with a schema migration (schema-only is allowed by `research_tooling_separation`); a data migration ships on its own (R6).
- **W6 Migrations are append-only, and are numbered when the PR is opened and re-pinned at merge.** A schema deletion is a new compensating migration. A column that a committed data migration INSERTs is never dropped (rule 5): writer-retire, reader-retire, stop. A *table* that a committed data migration INSERTs into may be dropped only when an `AFTER_DATA` marker postdates those migrations (migration 095's marker is the mechanism), and the step quotes the grep and the `--rebuild` result: `grep -nE 'INSERT INTO "?<table>' scripts/migrations/data_*.sql`. **A schema migration that backfills from existing rows, adds a CHECK that existing rows must satisfy, or renames or rebuilds a table that data migrations dated after 20260920060857 write to, declares `-- AFTER_DATA: <timestamp of the latest data migration>`, as migration 093 does** (`migrate_db.py` `build_plan` then replays it after those data migrations). Without the marker a schema migration numbered after 095 replays before them, and the blocking `migration_reproducibility` goes red. **Where a marker is not load-bearing today it is still correct**: it records the chronology (rehearsals of R24 and the marker column showed `--rebuild` identical without it), so a plan must not claim the rebuild fails without it unless the step proves that. **Numbering:** T1 takes 102 to 105; every other migration takes the last used number plus one when its PR is opened (`ls scripts/migrations/[0-9]*.sql | tail -1` prints the last used) and is re-pinned if another PR merges first; a rehearsal's numbers are not carried over, and prose names a migration by its slug, never by its number (the Phase 1 rehearsal wrote one into CLAUDE.md, where it goes stale on renumbering). A data migration written through `emit_data_migration.py` ships as a **data-only PR**, apart from tooling and from any research batch (DR-2026-09-26 §7, RC6).
- **W7 Antagonist before each PR.** A read-only Fable 5.1 pass on the diff, findings verified against sources before they are applied. A review, not a proof. The ledger bars a pass on a plan or on a pass without a fresh owner commission (LED-068, LED-210; the 2026-10-09 amendment is "for that plan only"). The owner commissioned the passes on this plan in session on 2026-10-12 ("antagonist runs to ensure 100% accuracy", a message absorbed mid-turn: `transcripts/harness_db856d85/main.jsonl:4139`); the ledger holds no entry for it, so step 2.1 records one.
- **W8 Run from the repository root.** The transcript hook writes under the working directory; step 0.4 removes the cause.
- **W9 The instrument shrinks as it works.** A step that resolves a conflict deletes its entry from `conflicts.yaml`; step 0.6 makes the quote check apply only to atoms still cited.
- **W10 Rehearse in the plan's order, in a clone whose `origin/main` is the PR's base.** The changeset-scoped gates (`attestation_*`, `research_tooling_separation`) read `origin/main..HEAD`; set the clone's `refs/remotes/origin/main` to the base commit or they read other people's data migrations as the step's own.
