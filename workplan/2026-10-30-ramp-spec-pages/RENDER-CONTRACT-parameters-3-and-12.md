**Status: DRAFT, unratified.** Written 2026-10-30 by the session `session_2026-10-30-ramp-spec-pages-rebuild`, revised after an adversarial round (a read-only Opus critic, in `transcripts/harness_fcb93ff6/subagents/`). It is a design document: no renderer, no HTML and no schema change is made here. The owner has not ratified it. The owner's statement of 2026-10-30 (`references/project-standards.md`, "Owner statement 2026-10-30") restates the posture ratified in `decisions/DR-2026-07-21-product-posture-thinking-tool-not-authority.md`, and the contract is written to that posture.

**Derive every figure.** Counts and states in this file are not typed; each element names a probe. Run `python3 -I scratchpad/session_2026-10-30-ramp-spec-pages-rebuild/contract_probe.py` (read-only; it prints `EXAMINED:` as rows examined) and read the line for the element id. The probe is a working, not a check; it is registered nowhere.

## 1. What this is, and what it is not

CLAUDE.md names the render stage: *book surfaces, read from the database when rendered; no committed file is one* (2026-08-27). The owner's invariant (`owner-rules/contract-traceability-invariant.md`) is that every boundary has a contract that can be verified, and an untraceable hand-off is a defect. HANDOFF.md section 5.6 asks for this document before any HTML: **page element → required data → table.**

The page is for **a ramp** (term TERM-089) with two sections, **ramp gradient** (parameter 3, TERM-001) and **ramp run length** (parameter 12, TERM-091). Per owner ruling OR-14 (2026-10-29) it is derived from a typed term pointer to the live determinations of its parameters. It is never a container rows are filed into and carries no item code.

The elements hold whichever way the owner answers OW-1b (how the prose is produced) and OW-1c (whether the render table is stored or rebuilt): those choices change how text is produced and kept, not which inputs an element needs. Section 5 states the one record shape both share.

**Relation to `RENDER-DECISIONS-AND-PIPELINE.md`.** Another session, working in parallel, recorded the owner's render decisions of 2026-10-29/30 in the ledger ("Owner rulings 2026-10-30", and its second entry) and wrote a first-pass element table (its section 3, from `PRAGMA table_info`). This contract is the probe-backed, adversarially reviewed version of that table for parameters 3 and 12 and is to be read with those rulings: best practice names the most accommodating value found (the ledger's item 1, with the ○ band and flag kept); the page offers an audience lens and a disability lens (item 4); rows with no value are not shown and the Gaps section states them (item 9a). Where its section 3 and this file differ for these two parameters, this file is the more recent.

It is not the page design. Layout, type, colour, grid and the WCAG 2.2 AA tests are in `reports/spec-page-design-requirements-2026-10-29.md` (R1 to R16) and are carried over by reference. **Accessibility is never self-certified** (owner standing rule).

## 2. Rules every element obeys

- **C1. No value without a pointer.** Every figure carries an `extraction_id` that reaches `evidence_sources` on `ref_id`, a verbatim `claim_text` and a locator. (Probe I1.)
- **C2. The renderer selects, groups, counts and formats; it never composes a value.** Which value stands for a cell, which cap is the most accommodating, how divergent rows are reconciled and the spread note are the engine's (workplan T-2 to T-4; owner OR-4, OR-6b). Where several rows answer one cell, all are listed in a fixed order with their conditions and none is chosen.
- **C3. A displayed determination has its marker.** Unmarked is an error (CLAUDE.md section 6); the marker lives on `specifications.marker`. A row read straight from `source_value_extractions` is shown only as a sourced reading, labelled with its source's evidence type and tier and its own `extraction_status`; it is not offered as a determination.
- **C3a. A marker describes the evidence; it is not an endorsement.** ●, ◐ and ○ state how well the evidence behind a figure stands, in words beside the symbol (the plain-language translations are armature section 4.7, which `governance/held-tensions.md` T5 preserves).
- **C4. Absence is rendered, not hidden and not invented.** A cell with no live determination prints its gap (`v_pending` with its gap). It never prints "Not set" and never fills the cell from a neighbour. Under the owner's earlier "no Not-set rows" instruction such a cell is not a table row; it is named under Gaps.
- **C5. State is shown as stored.** `extraction_status` and the source's verification print as they are, with the flag OR-11b requires for a `preliminary` figure. OR-11a says `verified` requires a full-scope scan; the build reports the `verified` rows that lack one, so the page prints no more confidence than the scans support. **A recorded identity or edition error is printed with the row, never corrected silently** (C10).
- **C6. The renderer shows each figure in the source's own unit and converts only through the engine.** `assess_cell.NOTATION_FAMILIES` owns one family, gradient (`%` and `rise:run ratio`), and refuses degrees. OR-10's length conversion (inches and millimetres, rounded to a quarter inch or 5 mm) is an engine step that is not built (workplan T-1b step 9). Until it is, the unit controls offer only what the engine can convert, and every other figure prints as stated.
- **C7. Traceability to bytes.** `retrieval_log.artefacts_for_source(ref_id)`: where none exists the page says the source was read from a live page and no bytes are held (probe E14).
- **C8. Radical transparency, the posture of DR-2026-07-21 and the owner's statement.** Each element shows what it rests on: source, locator, the state of the reading and, for a determination, the rule version, the derivation, the strength flag and the disagreements. The record behind an element carries the hash of its inputs (I6); the page footer carries the database's schema version and file sha256.
- **C9. Voice: describe and attribute; do not adjudicate a correct path.** The guidebook's own voice says what a source states, where, and in what state ("the Irish Technical Guidance Document M, 2022, Table 2, states ..."). It does not say a value is correct, safe or adequate, and it uses no "should" or "must" of its own; a source's "should" or "must" is quoted as the source's. **"Best practice" is not banned**: the ratified register map (`governance/evidence-architecture.md` section 6) renders "best practice: X [●]", and the posture DR defines it as the practice the evidence best supports, offered as a figure for thought. It may appear only as that map defines it, with its marker, its derivation and its disagreements in view, never as a bare endorsement. The ledger of 2026-10-30 (item 1 and its second entry) rules that the value named as best practice is the most accommodating one found in the parameter's direction, and that a value resting on T4 to T6 alone keeps the ○ band and the weak, code-derived flag; the phrase stays, under those conditions.
- **C10. Supersession and recorded errors are shown, not smoothed.** A source with `superseded_by_ref_id` is shown as superseded and its rows are not listed as a separate current reading. A source whose own notes record a wrong stored field (a year, a title, an edition) prints that note beside the entry. Two ref_ids that are one instrument print as one entry, "also admitted as ..." (probe E2.dup).
- **C11. Evidence type is shown with the tier.** A Co-1 source is labelled Co-1, co-primary with T1 (CRPD Art 4.3; CLAUDE.md section 6), never as "T1" because its stored tier is 1.

## 4. Invariants the build is to verify

Each is stated so a check could be written; **none is registered** (CLAUDE.md section 8: nothing is added without naming what reads it, so a check waits for the renderer that would read it).

- **I1.** Every numerical row printed has `extraction_id`, `ref_id`, a verbatim `claim_text` and a locator. (Probe I1 tests it.)
- **I2.** A row with no condition edge makes no claim about conditions. (Probe I2 reports how many rows carry a condition in prose instead.)
- **I3.** No figure on the page is composed by the renderer. Review, not a check.
- **I4.** A displayed determination's state is one of `stated`, `provisional`, `pending`, `not_applicable`, and only with a live determination.
- **I5.** Each source printed has an author row and a year, and no source is printed as a current reading if it is superseded or a duplicate admission (C10).
- **I6.** Each element's record carries the hash of its inputs; the page footer carries the database's schema version and sha256.

## 6. What the held data can and cannot fill

- **There is no "preferred" or "maximum" field.** The schema has `comparator` and `figure_role` and nothing marks a figure as preferred. The earlier page's two columns are replaced by **Limit** (one line per claim row), **Applies when** (its condition edges) and **The source's wording** (its own sentence, quoted, which is where a source's own "preferred" or "recommended" appears). Rows such as the Irish preferred maximum and the French "recommended, not required" figure carry that status in their text, so the page shows the text beside the figure and does not hide it in a popup.
- **"Between landings" is parameter 12**, filled for some of the in-scope jurisdictions only (probe E2.p12).
- **The earlier page's other columns are not parameters 3 or 12**: landing size, clear width, handrails, cross-slope. Landing dimensions are TERM-092, not minted (GAP-071); the others have no parameter. They are outside this contract.
- **The old staged data** (`data/E-03.json`) is compared by probe X1 and is to be superseded, not loaded.
- **Data defects the page would otherwise print as fact**, each a data task and not this contract's: an admission whose stored year and edition are recorded as wrong; a source recorded with a wrong year; a source superseded by another; one instrument admitted under two ref_ids (batch 23); a population match whose grade and note disagree; a figure's condition held only in the unit or the sentence. The probe's E2.dup, E7 and E10 lines count them.

## 8. The five questions: the assistant's proposals after the adversarial round

The owner's reply to the first draft deferred these ("i don't know how to resolve the questions for me at this point"). The Opus critic attacked the first version of the proposals. **None below is a ruling; none binds a later session.**

1. **Preferred versus maximum.** *Proposal (survives with a change):* no typed "preferred" field, but the page shows the source's own wording beside every figure (section 6), so a source's own "preferred" or "recommended" is visible in the table, attributed to the source.
2. **Absolute versus unrecorded.** *Proposal (survives with a change):* the first version printed "no condition recorded in this reading" for a row with no edge. The critic showed that is false for rows whose unit or sentence states a condition, and that `--relation none` is an extractor's explicit statement that the database does not keep. The page therefore makes **no statement about conditions** for an edgeless row: it prints the source's sentence and the reader reads it (E12). Recording the extractor's `none` is a possible tooling change; the earlier reason against it ("it would invite the guidebook to assert") is withdrawn, because such a field would hold an attributed reading as `condition_on` does. Moving prose conditions into edges is D-1.
3. **A pointer from a gap to a parameter.** *Proposal (survives with a change):* defer until S-1 has written pending specifications and a recorded gap still cannot be reached. A recorded gap can concern a term that is not a parameter (GAP-071 concerns TERM-092), so any pointer must be able to key a term. Until then the page says recorded gaps are not reachable by parameter.
4. **Per-role rendering (audience lens).** *Resolved by the ledger of 2026-10-30, item 4, which records the owner's statement that there is an audience lens and a disability lens.* The first version of these proposals recommended dropping it; the critic showed that `governance/held-tensions.md` T5 and DR-2026-07-21 keep it, and the ledger entry written meanwhile by another session agrees. What is left is a data question: where each role's emphasis lives (E13).
5. **OW-1b and OW-1c.** *Needs the owner.* The first version proposed templates and rebuilt. The critic showed that templates cannot render a source's sentence in another language into English, that OW-1b's own prompt reserves the question of who writes prose to the owner, and that "a rebuilt table has nothing to go stale" is untrue of the deployed copy a reader sees. The question for the owner: may the page show a translation or rewriting of a source's sentence at all, and whose voice may it be in? Until answered, sentences appear verbatim. These prompts stay open on the owner's browser page. The same session's ledger entry also lists them as still waiting on the owner.
