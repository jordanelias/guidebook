## 3. The problem, in the guidebook's terms

The guard against a number that is attached to a quote and not read from it compares digit runs as substrings of a quote stripped of punctuation. A figure with a shifted decimal point or a missing colon is accepted under a quote that verifies, and can then govern a published value. A figure the source writes in words ("vijf procent", "viisi prosenttia") has no route at all: it is either stored as words, which the engine cannot read, or passes by accident when its digit happens to occur elsewhere in the quote.

## 4. The change

Order of preference, from CLAUDE.md §8: do nothing and say why; change a rule or convention; reuse what exists; delete the cause; only then add the smallest code that closes the defect.

1. **Read numbers before punctuation is removed.** One reader, beside `normalise_quote` in `scripts/research/retrieval_log.py` (one home; do not write a second normaliser). It returns the number tokens a text states, each with the readings it can have: a decimal point or a decimal comma (`1.2`, `1,2`); grouped thousands with a space, a no-break or thin space, points or commas, or Indian grouping (`1 200`, `1.234,56`, `1,234.56`, `1,50,000`); a symbol ratio (`1:12`, `1/12`, `1∶12`) as one ratio token. A single group of exactly three digits after one mark (`1.200`, `1,200`) is ambiguous and carries both readings. On the quote side only, the operands of a symbol ratio and the pieces of a space-grouped number are also stated numbers (`AS 1428.1:2021` states 1428.1 and 2021; a table cell `800 750` states 800 and 750). Signs and units are not read. The existing conversion of CJK numerals (`_cjk_to_arabic` in `scripts/db.py`) is applied to the quote first, as today, and is not extended. **No list of number words or ratio words of any language is written in code.**
2. **Compare as numbers** in `scripts/db.py`, `_require_verbatim`, the `claimed_value` block (`grep -n 'def _require_verbatim' scripts/db.py`). Rules, in this order: (a) an ambiguous token in `claimed_value` is refused, asking for the unambiguous form (`1200` or `1.2`); (b) a claimed ratio is stated when it equals a symbol ratio the quote states, or when each of its operands equals, once, a number the quote states as a whole token: not an operand of a symbol ratio and not a piece of a space-grouped number, which item 1 emits on the quote side only. This covers a ratio the quote writes in words (`1 in 12`, `1 zu 12`, `十二分の一`). So `1:1` fails under a quote that states only `1:12`; `1:12` fails under "not steeper than 1:20 where the run exceeds 12 m" (its 1 is only an operand of `1:20`); and `1:12` passes under "AS 1428.1:2021 requires a gradient of 1 in 12". Chosen (pilot 2026-11-13): the earlier rule ("must equal a symbol ratio the quote states, if the quote states any") let a cited standard number such as `AS 1428.1:2021`, which item 1 reads as a symbol ratio, disable operand matching for every ratio written in words beside it; limiting operand matches to whole tokens closes that and the `1:20 … 12 m` case with one rule and no list. (c) every other claimed number must equal a number the quote states (here operands and pieces count, so a plain `12` passes under `1:12`); (d) a claimed number whose only match is an ambiguous quote token, or that fails (b) or (c), is *not stated as a numeral*: see item 4. This is not a separate hard refusal: the row is refused unless item 4's wording is given and passes item 4. Known and accepted: a plain `12` passes under `1:12` (12 is stated), and a ratio written in words is matched by its operands only.
3. **The column.** A schema migration adds `source_value_extractions.value_as_written`, TEXT, nullable, with a CHECK that it is not blank when present. It holds the source's own wording of the figure, exactly as it stands in `claim_text`, where `claimed_value` is a reading of that wording and not a copy of a numeral in it ("viisi prosenttia" for `5` and `%`; `1,200` for `1200`). One cell, one fact: the span of the quote that the numeral and unit translate. The numeral stays in `claimed_value` and the unit in `claimed_unit`. NULL means the quote states the claimed numbers as numerals. Add no view and no check. The owner's ruling behind the column: `grep -n -F "just translate these into numbers/units" references/project-standards.md`.
4. **The rule on the column, in the same function.** When every claimed number is stated as an unambiguous numeral in the quote, `value_as_written` must be absent, and is refused if given (the column is not for copying numerals). When some claimed number is not, `value_as_written` is required: it must occur in `claim_text` under the same normalisation the quote check uses (so it is in the verified bytes), **and it must not itself state a different figure**: read `value_as_written` as written with the item-1 reader, claim side (no CJK conversion, no operands or pieces), and refuse it if any token it yields has a single reading, or has no claimed number among its readings. The row is then accepted. So "vijf procent", "viisi prosenttia" and "1,200" (for `1200`, or for `1.2`) pass; "1.2 m" for `12`, "1:20" for `1:12` and "1,200" for `9999` are refused. Chosen (pilot 2026-11-13): as first written, this item accepted `12` under "no higher than 1.2 m" with `--value-as-written "1.2 m"` and `1:12` under the `1:20` sentence with `"1:20"`, which restores behind one flag the decimal shift this task exists to refuse (pilot D1); the added condition reuses the item-1 reader and names no word of any language. Known and accepted residual: a wording that contains no numeral is not checked for meaning, so `9999` with `--value-as-written "higher"` under "no higher than 1.2 m" is accepted. That the wording means that number is the extractor's judgment: it is recorded by the column and the row's session, and it is what the adversarial pass and a reviewer check. Say so, residual included, in the function's comment; do not add a table of number words to check it mechanically.
5. **A figure with no numeral.** For a `claim_type` that states a quantity, a `claimed_value` that contains no number is refused. The message says what to do: enter the numeral in `--claimed-value` and the unit in `--claimed-unit`, and give the source's wording in `--value-as-written` (the owner's ruling of 2026-11-12). Which claim types state a quantity is a judgment about the vocabulary, not something the CHECK can say: declare it once, as `dbcore.QUANTITY_CLAIM_TYPES = ("numerical", "range")`, with a comment that names it as a judged rule and a test that every member is in `dbcore.check_values` for `source_value_extractions.claim_type`. Nothing else types those two words. The rule receives the row's claim type as a keyword argument named `claim_type`; `insert_extraction` and `amend_extraction` pass the row's own. Chosen (pilot 2026-11-13): a call that gives no `claim_type` (None) is treated as a quantity, so a caller that omits it gets the stricter rule, and the evidence command of section 3 (which cannot pass the argument, because today's function does not take it) prints `REFUSED` for `twelve` after the change; a call that means `qualitative` passes it. `--verbatim-exempt` is unchanged: it is for text no artefact can carry, and is still refused when the text verifies. 6. **Writers.** `add-extraction` gains `--value-as-written` and passes it through `insert_extraction` to `_require_verbatim`. `derive-extraction` reaches the same function and takes no new argument. - the sweep of section 5 finds a caller (as defined there) that you cannot repair without adding something section 4 does not name. A caller you can repair is repaired and listed; a mention is left;

- `sha256sum data/guidebook.db` changes when this task has no migration, or the rebuild does not reproduce the database when it has one;
- you would have to guess a value, a vocabulary term, a name or an owner's intent.

## 10. Rollback

Before merge: close the pull request and delete the branch; nothing else has changed. After merge: `git revert <merge commit>` in a new pull request. A migration that has been committed is never edited or deleted: fix forward with a compensating migration (CLAUDE.md rule 3). Never rewrite history.
