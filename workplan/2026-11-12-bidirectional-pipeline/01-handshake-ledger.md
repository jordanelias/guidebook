## 2. Warrant classes and the corrections applied to the top-down ledger

### 2.1 Classes

| Class | Meaning | How it binds |
|---|---|---|
| OWNER | The owner's words, quoted in the ledger or a transcript | Rule 0: supersedes every prior record it touches, on contact |
| LEDGER | A reading, ACTION or condition a session wrote under an owner ruling | Binding where the entry says so; `[ASSUMPTION]` marks are unratified |
| CONTRACT | `pipeline-contract.yaml` or `research-contract.yaml` text | The pipeline contract was accepted as doctrine on 2026-07-21 as a five-stage Level-2 index with one owner-action precondition recorded outstanding (X26); its header still says PROPOSED and its stage list is now the seven-stage one; a later owner ruling overrides its content |
| DOCTRINE | Canonical governance documents | Binding unless an owner ruling touches them |
| LAYER0 | `CLAUDE.md` | Process rules; yields to rule 0 |
| RELAYED / MEMORY | Owner statements reported but not recorded, or an assistant's note of owner direction | Not verbatim owner prose; flagged on each row |
| ASSUMPTION | An inference with its basis named | Binds nothing |

A row's status is LIVE, SUPERSEDED (by what) or CONTESTED (two live texts disagree; the conflict is named, not weighed).

## 3. Requirement table: REQ-001 to REQ-100 and HS-A01 to HS-A18

One position per row; the position number is the row's order. **One rule for the verdict (P-01-182), applied to every row and every boundary.** A verdict states how today's code and data stand against the requirement text as worded; the class and status columns say how far the text binds, and a non-binding row (ASSUMPTION, MEMORY, RELAYED, agent design) carries a verdict flagged as such. MET: a refusing writer, a schema constraint or a blocking check enforces the clause, its subject is non-empty, its failure path was provoked or is named untested, and no scope gap inside the clause is known. PARTIAL: a mechanism performs or detects part of the clause, or enforces it for part of its scope, or the data comply while nothing enforces. UNMET: no mechanism performs the clause's verb, or the owner's ruling is not yet recorded or built, and no present code or row opposes it. CONTRADICTED: present code or rows do what the clause forbids or reverses, shown by an output, a query, code text or a counterfactual on a scratch copy; an absent record is never CONTRADICTED. UNPROVEN: the verdict needs a fact nobody has recorded, or a surface that does not exist, and the row names it. Where a writer now refuses what older rows did, the violating rows are counted by command and the verdict is PARTIAL. A zero-row object is unproven, not clean (CM rule 4): a typed key on an empty table is a mechanism that has not run. The top-down side is the verbatim warrant and its line; where a row has none, the word ASSUMPTION stands. Quotations were re-resolved by [X23]. ## 5. Direction matrix, derived

Derived from the instrument's own output, not copied from BU section H. Rows are the stage entered, columns the stage reached.

```

python3 -I - <<'PY'
import json
d = json.load(open('walk.json')); S = d['spine']; P = d['pairs']
def cell(r, c):
    if r == c: return '='
    i, j = S.index(r), S.index(c); a, b = (r, c) if i < j else (c, r); p = P[f'{a}->{b}']
    z = d['zigzag'].get(f'{a}<->{b}'); zp = d['zigzag_populated'].get(f'{a}<->{b}')
    if i > j and p['up']: return 'P' if p['direct_fk'] else 'p'
    if i < j:
        if p['send_fk']: return 'R'
        if p['down']: return 'j'
    if p['views']: return 'v'
    if z: return 'z' if zp else 'z0'
    return '-'
print('%-14s' % '', *['%-13s' % c for c in S])
for r in S: print('%-14s' % r, *['%-13s' % cell(r, c) for c in S])
PY
```
